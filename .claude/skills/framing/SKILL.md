# Постановка задачи (S0–S1, решение G1)

**Цель:** превратить размытый запрос в точный вопрос с целью, метрикой успеха, получателем, ограничениями и режимом работы, задав минимум вопросов.

## Шаги

1. **Проект.** `python3 strateg.py new <имя-латиницей>`. Присланные файлы положи в `projects/<имя>/materials/` как есть, ничего в них не меняя. Запрос пользователя дословно запиши в `project.json` (поле `request`).
2. **Быстрый просмотр (S1.0).** Без полной расшифровки посмотри названия файлов, первые страницы, заголовки таблиц и разделов. Задача — понять, что уже есть, чтобы не спрашивать об этом. Полный разбор — на S2.
3. **Тип запроса.** По `knowledge/request-types.md`: диагностика («почему падает»), запуск («кому и как продавать»), коммуникация («что сказать»), смешанный. От типа зависят вопросы исследования и методички.
4. **Точный вопрос.** Сформулируй: какая метрика или какое решение, у кого (сегмент, продукт), с какого времени, что будет сделано по ответу. Плохо: «почему падает удержание». Хорошо: «почему с мая падает доля платящих на третьем месяце у новых подписчиков сервиса и что сделать до конца квартала».
5. **Цель.** Предложи 2–3 трактовки цели с метрикой успеха. Подсказки: прибыль на коротком сроке; прибыль на долгом; больше клиентов, ради которых готовы чем-то пожертвовать; удержание; запуск; понимание ценности аудиторией; сокращение затрат; проверка гипотезы.
6. **Вопросы G1.** Не больше пяти, к каждому — ответ по умолчанию. Спрашивай только то, чего нет в материалах:
   - какая трактовка цели верна;
   - кто получит результат (руководитель, команда, инвестор) — от этого зависят глубина и формат. **Пользователь и получатель — разные роли:** с тобой работает пользователь (например, руководитель продукта), а результат может быть адресован другому человеку (например, директору). Не называй пользователя ролью получателя;
   - ограничения: срок решения, бюджет, технические и юридические рамки;
   - какие ещё данные есть или можно получить;
   - режим: экспресс, стандарт или глубокий — с оценкой времени и токенов из `config/modes.json`.
7. **Запись.** Заполни `project.json`: question, goal, success_metric, user_role (кто ведёт проект с тобой — его роль, из запроса или ответа на G1), recipient (кому адресован результат), constraints, mode, sources (если пользователь ограничил источники). Ответы по умолчанию, которые пользователь не подтвердил, запиши в state.md в «Допущения». Ответы пользователя — это материал проекта: заведи на них SRC «материал пользователя, сообщение в чате от ДАТА».
8. **Конец этапа.** `python3 strateg.py check <имя>`, `python3 strateg.py snapshot <имя> S1`, state.md: «Этап: S1 · 2 из 12», дальше — S2.

## Чего не делать

- Анкету из 10–15 вопросов.
- Вопросы, ответ на которые есть в материалах.
- Выбирать цель за пользователя. Предложить — можно, решить — нет.
- Начинать исследование до ответа на G1. Исключение — пользователь сам сказал «решай сам»; тогда бери ответы по умолчанию и пиши их в «Допущения».
